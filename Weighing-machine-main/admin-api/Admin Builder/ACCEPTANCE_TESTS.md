# Acceptance tests — single-frame workflow

## Functional

- [x] A user can upload one full-size original and draft a camera profile by drawing one timestamp ROI; no 5–10 frame upload is required.
- [x] No editing-mode and lighting-mode dropdowns appear on the routine screen. Automatic lighting accompanies every normal job.
- [x] With an uncalibrated camera, the app offers a **clearly identified display-time annotation** and lighting preview, instead of falsely claiming an authentic timestamp replacement.
- [x] Legacy in-frame rendering is recorded as a simulation requiring review; hidden-pixel recovery is not called exact. The routine UI does not enable this strategy.
- [x] Profile reuse requires explicit camera/view selection and matching dimensions/framing. An explicit profile mismatch bypasses its ROI and adds a review warning; resolution alone never selects a profile.
- [x] The UI shows original/derivative and centered report-slot crop previews. The appended annotation preserves all source-scene pixels; the report crop is non-destructive.
- [x] Save is explicit; preview remains temporary. Unique IDs and collision-safe writes are preserved.

## Image integrity and QA

- [x] Original source file bytes/hash remain unchanged before and after processing.
- [x] Original in-frame timestamp remains in the source-scene area; requested display time is appended and separately labeled.
- [ ] Exact requested digits, leading zeros, timestamp geometry, font softness and clipping are checked when an in-frame simulation is generated.
- [ ] No sharpening, invented lights, new buildings/tyres, or changed weighbridge/yellow rod/garbage.
- [ ] Night and daytime scenes receive conservative time-appropriate transforms and any major visual uncertainty is reported.
- [ ] Any background inpainting is clearly identified as estimated, not authentic recovered pixels.
- [x] Every exported derivative remains recognizable as edited without a sidecar.
- [x] Report preview shows the 5:3 centered cover crop and quantitative edge crop. It explicitly warns when the crop trims the appended requested-time caption; actual truck/ramp clipping remains subject to human review. No report copy or JPEG conversion is generated by the prototype.

## Test inventory

1. Single camera frame without clean background reference: annotation fallback works and reports limitations.
2. Same camera second frame: saved ROI/profile reused after verification.
3. Other camera at same resolution: no false profile reuse.
4. Cropped/resized frame: mismatch warning and manual ROI review.
5. Day and deep-night targets: visually inspected transforms on source image, no fabricated lighting.
6. Missing/corrupt image, strange filenames, large payload: appropriate errors.
7. Restart and saved-image retrieval: file/hash/manifest still valid.
8. Regression: existing 21 automated tests and targeted new cases pass; tests do not count as proof of photorealism.

## Current validation

- Prototype suite: 23 tests pass, 0 fail.
- `3515-ac1.png` (1619×971) processed through the UI using the
  `ANNOTATED_DISPLAY_TIME` strategy. The 50-pixel caption band extends output
  height; the captured scene itself is not resized or covered.
- The actual report-slot preview removes about 25 pixels from the top and
  bottom. It also trims about 25 pixels from the bottom of the 50-pixel
  requested-time caption, so the requested time may be clipped in that report
  slot. The source's upper-left timestamp is at risk of clipping; inspect
  truck/ramp/yellow-rod visibility manually. The prototype now surfaces this
  caption-specific warning before saving or downloading.
- One-frame calibration has only been functionally tested with synthetic
  input; the real CCTV view has not yet had a profile ROI selected and reviewed.
- In-frame timestamp replacement and real-camera lighting realism are not
  validated. No hidden scene pixels are claimed as recovered.
